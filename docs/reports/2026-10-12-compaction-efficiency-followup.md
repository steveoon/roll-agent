# Task 3 压缩效率跟进：真实任务为何只释放 13%

本轮在现有 `dev` 工作区修复并验证。Task 4 未展开；没有提交、push、发布、重启用户会话或修改用户模型、thinking、审批配置。并行授权任务已独立提交 Core 修复 `ece7908`，本轮没有修改其文件。

## 结论

13% 的直接瓶颈是 **完整证据批次过小，串行摘要耗尽同一个 120 秒维护期限**。前一轮补齐完整原文后，预算仍把 `contextWindow / 2` 的 token 数直接当字符数使用。128k 测试窗口每批只有约 64k 字符，真实模型来不及处理足够批次。

另发现一项保守误拒绝：原文的一整行包含多个句子时，校验器按句号和换行同时拆开，拒绝了逐字引用的多句事实。它没有丢掉原文，但会阻止本来可以安全提交的压缩。

最终同一编码夹具的配对实测：未压缩和压缩组均通过 14/14；优化后释放 **70.14%**，压缩后占测试窗口 **26.68%**。把关键要求放到长文本中部和尾部的第二种夹具，释放 **72.71%**，压缩后占 **24.79%**，编码同样通过 14/14。

## 可复核的根因证据

在修改生产代码前，给 opt-in benchmark 加入每次摘要的实际耗时、输入/输出 usage、现有 compaction debug 事件记录。这属于测试采样，没有新增产品持久化诊断协议。

同一 128k / 20 轮夹具重现 13%：

- 第一批只展示 8 条 evidence；Provider 报告输入 9,727 token、输出 1,603 token，耗时 **69,177ms**，提交后移除 6 条原始消息。
- 第二批只有剩余约 51 秒，在 **50,783ms** 后返回 `TimeoutError`，没有提交。
- 同口径完整请求估算从 **114,356 → 99,491**，释放 14,865，即 **13.00%**。维护结果 `advisory_target_miss`。
- 此后编码阶段另有网络中断，不能算质量通过。上一轮同样压缩规模的成功编码样本仍单独保留，不与本轮网络失败混为一谈。

优化后一次批次展示 32 条完整 evidence；最终配对样本 Provider 报告摘要输入 **42,063 token**、输出 **1,944 token**，耗时 **67,293ms**，一次移除 30 条原始消息，维护结果 `ready`。

这说明原来的低释放量不是所有剩余内容都必须保留，也不是 75% 软触发阈值本身要求停在那里。实际限制是每次生成处理的有效范围太小。

分散事实夹具还独立复现了引用误拒绝：模型输出准确的多句原文引用，旧校验拒绝 6 项，原文全部保留，移除 0 条。修复边界校验后重新调用真实模型，0 项拒绝、移除 30 条，5 组完整要求全部进入 checkpoint 和后续每一次模型请求。

## 为什么离线结果不能直接外推

前轮离线使用 350k/500k 窗口、30–100 轮不同密度历史，摘要由确定性 mock 立即返回；真实编码夹具是 128k 窗口、20 轮，摘要需要数十秒。它们既不是相同输入，也没有相同的成本。

离线测量可以验证生产准备、覆盖、持久化和请求大小，但不能证明真实模型在 120 秒内能处理多少批，也不能证明自然语言审阅或代码完成质量。此次保留离线结果作为结构回归，真实编码成功单独判定。

另外，Provider usage 回来后会修正估算残差。这个校准造成的数字降低不能计入压缩释放。本报告的释放率统一使用维护前后 **未校准的同一请求估算**；它是 UTF-8 byte/3.5 启发式，不是 Provider 的精确 tokenizer 结果。摘要 usage 单独列示。窗口 128k 是隔离测试夹具设置，不是改写用户配置。

## 实现范围

- `compactor.ts`：复用真实 `Output.object` schema，先扣除 system、schema、Provider options、输出和误差预留，再计算证据 token 预算；最终 SDK 准备好的摘要请求再次校验后才允许派发。未知窗口继续保留保守的字符上限。
- `agent-session.ts`、`compaction-semantic-state.ts`：按 UTF-8 token 估算装入完整证据，仍限制最多 32 条、连续覆盖和两条证据通道。已知窗口额外保留 1M 字符资源上限；不裁剪单条来源来凑预算。
- 摘要输出省去缩进和重复解释，保留原文引证及完整审阅；没有换模型、降低推理强度或增加 120 秒期限。
- 引文必须逐字匹配来源，起止落在完整行/句子的边界；允许连续完整句子。缺否定词、句中截断、改写空白仍拒绝。该修复不把模型自己写的 `text` 当成事实。
- 原文退休仍要求覆盖、审阅和实际 reminder 事实可见性全部通过。拒绝、不确定、reminder 容量不足和未知工具结果的保护保留；未改 Task 4 持久化协议。

真实配置：`chatgpt/gpt-6.1-sol`，普通及摘要 effort 均为当前配置的 `medium`。模型在隔离临时目录实际读取、修改和验证 `retry.mjs`；宿主独立执行 14 项功能检查，检查代码导出而非相信模型完成声明。历史是受控构造，不能等同任意实际项目的质量保证。
