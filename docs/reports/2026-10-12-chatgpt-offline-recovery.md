# ChatGPT 网络切换恢复修复

在当前 `dev` 工作区实现，未提交、未暂存、未执行真实登录或续期。

## 行为

- 交互式 `roll chat` 先启动本地会话，使用配置模型和可选账号目录缓存；授权或网络暂不可用不会阻止进入基础 REPL / Ink。
- 启动后后台连接；发送前检查连接和凭证。过期凭证继续使用现有自动 refresh 流程，网络异常不清除凭证。
- 两种交互界面支持 `/reconnect`。重连只恢复连接，不重放消息或工具调用；失败保留会话、已提交输入和未提交草稿。
- 授权发现、JWKS、模型列表 GET 对网络故障及 HTTP 408/429/5xx 最多尝试三次（间隔 200/600 ms），每次读取流程共用 12 秒期限。交互连接探测整体期限 15 秒，可随退出取消。
- rotating token POST 不自动重试；Responses POST 遇到不确定的传输失败也不自动重发。已有明确临时 HTTP 响应的 SDK 重试策略保留。
- 模型缓存按账号注册身份隔离，有效期 7 天，不含凭证；发送前仍需成功获取在线目录并校验模型和推理强度。缓存不作为授权依据。
- 不改用户模型、推理强度、审批或压缩配置。一次性命令仍在初始化阶段显式报告连接失败。

自动重试是有界的；耗尽后可发送消息或执行 `/reconnect` 再尝试。refresh token 已失效等终态仍需重新登录，客户端不能替用户绕过授权。

## 二次审查后的四项修复

1. 续期的取消边界移至 POST 发出前：锁等待、发现和 JWKS 仍可取消；已发出的 token 交换使用独立的 30 秒期限，持有账号锁直到校验、保存完成。聊天取消只停止等待，不丢弃可保存的新凭证。
2. Core 在后台重连成功及发送前同步当前会话窗口，使用既有 Engine 切换接口重新应用当前模型，不修改 Runtime 源码。覆盖首次无缓存、旧缓存和显式窗口覆盖值；保持当前推理选项。
3. `/model` 使用同一个连接管理对象，保留发送前在线校验、错误状态与 `/reconnect`；API-key 启动仍不访问订阅授权服务。
4. 凭证锁等待支持可取消信号，连接等待独立受期限及退出控制。释放锁后不会发送已经取消的续期请求；已发出的安全保存工作可以完成。

发送预检失败交回 Runtime 的既有输入持久化路径，同一轮模型调用复用该错误，下一次提交或显式重连才重试。Ink 取消预检恢复文本及附件，预检自身不发送模型请求。
