# 在终端按项目使用 Roll Chat

`roll chat` 将新对话绑定到执行目录所属项目。Git 仓库内使用最近的工作树根目录，子目录与符号链接入口归到同一项目；不同 Git worktree 分开管理。非 Git 目录使用规范化后的当前目录。配置来源与项目归属彼此独立。

## 恢复与查看历史

```sh
cd /projects/a
roll chat                         # 在 A 创建新对话
roll chat --last                  # 继续 A 最近更新的对话
roll chat --list                  # 列出 A 的对话
roll chat --list --all-projects   # 所有项目及未分类历史
roll chat --last --all-projects   # 显式继续全局最近的对话
roll chat --session <id>          # 按 ID 明确选择对话，保留原项目归属
roll chat --view <id>             # 只读查看已提交历史
roll chat --view <id> --json      # 导出只读快照
```

当前项目没有可恢复会话时，`--last` 会报错，不会打开其他项目的会话。旧版历史没有可靠的项目来源，因此保留为“未分类”，可从全部项目列表查看或按 ID 恢复；不会根据当前目录自动重归类。

聊天内 `/resume` 打开对话历史，分为“本项目下的对话”和“旧会话”两组；旧会话指没有项目归属的会话。当前打开的会话也会列出并标注“当前打开”，列表初始选中它；选择它可直接返回聊天，不会重新打开或关闭会话。刚创建的空会话会显示“新会话，暂无消息”。当前项目没有其他历史时，旧会话仍可直接选择，无需额外命令。

Ink 列表显示每组数量，并将更新时间、消息数和状态按列对齐。“当前打开”以绿色显示，其他客户端“占用中”或“状态未知”以黄色显示；普通可用会话不重复显示状态。窄终端优先保留标题和状态，底部操作栏统一显示位置与快捷键；选中被占用的会话时，宽度允许则在操作栏显示占用客户端名称。

Ink 列表中按 Enter 继续所选会话；选中旧会话时，底部会显示 `m 归入本项目并继续`。当前打开的旧会话则显示 `m 归入本项目`，可以原地归类。基础 REPL 选中旧会话后提供对应的继续/返回与归类选项。归类保留原会话 ID、消息和工具历史，仅更新项目归属；成功后，当前项目的 `/resume`、`--list` 和 `--last` 都会将其视为本项目会话。归类当前会话失败时仍保留当前会话的占用与上下文。只续聊不会自动归类，已有其他项目归属的会话不能通过此操作移动。

`/resume all` 兼容入口和 `--all-projects` 仍可额外查看其他项目；`/view <id>` 只读显示历史。列表显示占用状态及已知客户端名称。只读查看不获取可写占用，不迁移或清理历史；其他客户端正在使用时仍可查看已经提交的数据。继续写入或归类时会重新原子获取会话占用。请先在另一端退出当前会话，再重试恢复。

## 选择配置来源

```sh
cd /projects/a
roll chat \
  --config /settings/roll.config.yaml \
  --config-workspace /settings
```

参数验证和相对资源解析遵循 [Runtime 配置上下文](runtime-config-context.md)。配置内相对的历史目录、Agent 数据、额外 Skills 和显式工程约定路径相对配置工作区解析；工具执行、自动项目 Skills 和自动发现的 `AGENTS.md` 继续使用执行目录。没有参数时保留原有发现及资源路径行为。

启动时固定所选配置文件，初始配置向导的检测、写入以及 Agent 初始化也沿用这一来源和资源工作区。当前聊天不会自动重读或切换到其他配置文件。由聊天创建的定时任务继承这个配置来源和资源工作区；执行时从原来源读取最新配置，不保存凭证。未发现配置文件而使用内置默认值时，保持原有无绑定任务行为。

## 查看当前配置与切换模型

Ink 与基础 REPL 的 `/status` 显示当前项目、启动时选择的配置文件和实际生效的 Provider/模型。Ink 的 `/model` 继续支持立即切换会话内模型，以及可选的设为默认；`/effort` 和 `/fast` 保持原有行为。

普通 `roll chat` 已移除 `/reload`，不再提供部分配置热重载。编辑 `roll.config.yaml` 后，退出并在相同目录、使用相同配置参数重新启动 `roll chat --last`，即可使用新配置继续当前项目最近的对话；也可用 `--session <id>` 明确指定原会话。历史与工具记录保留。当前聊天仍使用启动时的配置，文件被改坏或删除也不会因此阻断当前聊天。原有 `--provider`、`--model`、`--account`、`--fast` 启动参数继续覆盖文件默认值。

没有绑定配置文件时，`/status` 显示“内置默认配置”。聊天期间新建配置文件不会被自动采用，需要重新启动。

此调整仅限普通终端聊天。第三方 App 使用的 Runtime 配置重载、会话内模型切换、Protocol/Node Client 接口，以及兼容 `roll chat --server` 入口保持原有契约。定时任务仍在实际执行时读取绑定来源的最新配置。

## 升级共享会话库

共享会话库升级到 schema 12，用 nullable workspace 字段保存项目归属。正常运行 `roll chat` 时，旧库会自动备份、校验并升级，然后继续聊天，无需执行额外迁移命令或卸载后台调度服务。升级完成后会显示备份路径；再次打开不会重复迁移。

如果另一个 CLI、桌面端或定时任务正在占用该库中的会话，自动升级会停止，原有历史保持不变；退出占用会话或等待任务结束后重试即可。空闲的调度服务不阻止升级。备份或迁移失败会保留原库；未知的高版本库不会被降级。

需要单独维护时，仍可使用显式迁移命令：

```sh
# 确认使用该会话库的所有旧客户端已停止后执行
roll runtime migrate --confirm-stopped-clients
```

需要指定库时使用 `--threads-dir <dir>`。配置来自其他目录时，应使用该配置指向的实际历史目录。迁移会先创建并校验备份，已有会话消息和未分类状态保持不变。

支持的旧库仍可使用 `--list --all-projects`、`--view` 只读查看。schema 11 的旧 Roll 或旧 Desktop bundled Runtime 无法打开迁移后的 schema 12；共享库的 CLI 和 Desktop 都应先更新到支持 schema 12 的版本。外部 CLI 升级不会替换 Desktop 内置 Runtime，需要重新发布 Desktop 包。

新 Protocol 1.6 可选方法 `thread.browse` 和 Node Client `browseThreads()` 提供项目归属及只读占用信息；已有 `thread.list` 返回格式不变。Desktop 可通过此接口接入项目归属，Desktop UI 的采用需在其仓库另行完成。
