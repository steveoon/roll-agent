# Roll chat workspace and configuration experience

## Accepted behavior

1. Normal `roll chat` accepts `--config` and `--config-workspace` with the same validation/resource projection as `roll runtime serve --stdio`. With no flags, existing config discovery/resource behavior stays equivalent. Bind the selected source once; ordinary chat keeps its startup configuration. New schedules inherit the selected source, including a discovered file when available. Onboarding detection, writes, Agent registry/network and start environment follow the same source/resource workspace. Configuration paths contain references only, never serialized secrets.
2. Ordinary Ink and basic REPL retain read-only `/status` showing workspace, selected config source and the actual active model. Remove the incomplete CLI `/reload` feature, its controller adapter, reload subscriptions and operation admission lifecycle. Model/effort/Fast switching stays available with stale-selection protection. Editing configuration requires restarting and resuming the conversation; current chat is not blocked by external file errors. Runtime, Protocol, Node Client, Companion and legacy `--server` model reload/session model APIs remain unchanged, as do scheduler source bindings and execution-time config reads.
3. Persist a nullable, bounded workspace identity on new conversations, resolved by Core: canonical nearest Git worktree root (`.git` directory or worktree file), otherwise canonical execution cwd. Symlink aliases converge; different worktrees stay distinct. Runtime stores the identity without discovering paths or reading product configuration. New forks belong to the destination host workspace. Resuming does not silently change existing attribution. Old conversations remain unclassified.
4. `--last` and `--list` default to the current workspace's interactive conversations. `/resume` shows current-workspace and unclassified history together, in separate “本项目下的对话” / “旧会话” groups. The active conversation remains visible with a dedicated current-open status, initially focused; selecting it returns without a resume/close cycle. An explicitly opened cross-project active thread remains visible in its own group. An explicit “归入本项目并继续” action resumes with ownership and then assigns an unclassified interactive thread; it preserves the thread ID, timestamps and complete history. An active unclassified conversation can be assigned in place. Assignment failure releases only a newly opened target and preserves the active session. Existing classified threads cannot be reassigned by this action. `--all-projects` and the compatibility `/resume all` additionally expose other projects; `--last --all-projects` deliberately selects the global last conversation. No current-project `--last` match gives a clear error, never another project's history. Explicit `--session ID` remains an intentional cross-project selection.
5. Lists/pickers show session occupancy and owner label when known. Read-only inspection never creates/migrates/prunes history or claims ownership. Add `--view ID` and `/view ID` to inspect committed history while another client owns the conversation. Writable resume always acquires the existing atomic lease, including a final check after list display. No takeover, killing or automatic replay.
6. Shared host/Protocol browsing exposes workspace attribution and occupancy without changing frozen `thread.list`/summary payloads. Use an optional Protocol 1.6 `thread.browse` method, following the existing optional model-config method pattern; older clients keep existing payloads. Node client supplies the public helper. Desktop UI adoption is outside this repository; the shared contract is available for it.

## Architecture and compatibility

- Core: source discovery/resource projection, canonical workspace resolution, Provider/auth construction, terminal commands/presentation, schedule host-context injection.
- Runtime: shared workspace persistence/filtering, ownership inspection, execution/model-application coordination. No Core imports/types/config parsing.
- Protocol/client-node: bounded browse request/result schemas and public client method. Existing negotiation and legacy summaries remain unchanged.
- ThreadStore schema 12 adds workspace metadata. Existing histories follow the existing explicit backed-up migration contract; read-only supported old libraries remain readable and unclassified. No migration of real user data during development. New libraries initialize transactionally. Keep migration/ownership exclusion and higher-version refusal.
- Node >=22.13.0 for repository development; pnpm 11.24.0. No new third-party dependencies. Type stripping, strict optional properties, no `any`, `.ts` source imports. stdout is data, diagnostics are stderr.
- Preserve clack confirmation semantics, Skills/workspace instructions from execution cwd, scheduler admission/revision authority checks, per-thread leases, provider reasoning truthfulness, and background resource lifetimes.

## Acceptance evidence

Use isolated homes/config/history and a local traced model endpoint. Create A and B conversations in a shared library, update/close B last, then invoke `--last` in A and prove only A context reaches the endpoint. Check subdirectory/symlink/worktree identity and legacy unclassified exclusion. Exercise ordinary CLI startup-config stability after changed/invalid/deleted files, read-only status and restart/resume with updated endpoint/model. Verify third-party stdio reload, per-thread model isolation, MCP Sampling, and scheduled execution using bound configuration. Hold a real peer-process lease while listing/viewing and prove writable resume refuses until release. Typecheck/lint/unit/E2E/build checks and final adversarial review cover all changed contracts.
