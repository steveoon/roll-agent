# Windows 独立安装与更新长路径修复实施计划

## 目标与边界

Windows PowerShell 5.1、普通用户权限、未开启系统长路径策略且未安装 Node/npm 的用户，继续通过线上 `install.ps1` 完成首次安装、重复安装和升级。保留 ZIP、不可变版本目录和原子指针、固定 HTTPS 域名、SHA-256 校验、npm 渠道和现有数据路径。不得要求用户修改注册表、安装 PowerShell 7 或使用管理员权限。

旧版 0.38.0 更新失败时，重新运行新版在线脚本完成本体升级；配置、会话、Agent 与任务/服务使用锁均需保留。不覆盖已发布资产，不新增公开 CLI 或 Runtime/Relay 协议字段。

## 实现顺序

1. **反例与共享 ZIP 模块。** 先覆盖完整包超过 260 字符路径的失败。Core execution-environment 使用 yauzl 3.4.0 读取中央目录、预检查全部条目后流式解压；保留现有提取接口及 POSIX 路径。使用规范化绝对路径及 Windows 文件系统扩展路径，扩展路径不得进入 CMD 命令和用户配置。拒绝越界、盘符/UNC、反斜杠、设备名、尾随点或空格、重复/大小写冲突、文件目录冲突、链接/reparse point、特殊文件和加密 ZIP。上限为 100,000 条目、4 GiB 展开总量、1 GiB 单文件，验证实际大小和 CRC。取消时关闭文件句柄并等待子进程结束。
2. **PowerShell 引导。** 下载 ZIP 并校验大小、SHA-256 后，只提取唯一普通文件 `runtime/node.exe` 和 `app/bin/install-bootstrap.cjs` 到短临时路径。通过 JSON 参数文件启动该 Node，助手再次校验 ZIP 并执行全部深层文件操作。引导路径过长时及早报错；不包含助手的旧 ZIP 明确报告不兼容。PowerShell 只更新用户/当前会话 PATH 和清理短引导目录。
3. **安装与更新协调。** 助手由 esbuild 生成自包含 CJS，携带依赖许可证，无系统 Node、源码仓库及现场 npm 安装依赖。候选完整解压后加载内部安装协调器，执行安装身份检查、隔离启动检查、锁、重复安装比较与原子激活。私有 Node 退出后才能移动候选目录。现有安装走本体升级协调，复用 Agent registry、scheduler admission、维护锁与服务判断，不隐式更新全部 Agent。更新器共用 Node ZIP 模块，激活后明确使用目标版本环境。
4. **测试、发布与文档。** Core patch changeset 发布修复。六平台构建门禁保留，Windows x64/arm64 使用系统 PowerShell 5.1 验证完整 ZIP，专用 CI 中临时关闭长路径策略并最终恢复；用户电脑不修改策略。首次安装目录供 A→B 更新测试复用。Artifact 中间包保留 1 天，汇总包 3 天。保留无关 RFC 与工作区修改。

内部请求文件包括 schemaVersion、安装根目录、归档路径与摘要/大小、目标版本与平台、结果路径；结果包含版本、安装根目录与最终启动入口，不成为公开协议。发行 manifest schema 和顶层服务器文件数量不变。

## 恢复规则

下载、校验、解压或预检失败保持旧指针。活跃或身份不明的 Agent/任务拒绝激活，允许延后重启的服务报告延后，不强制终止。只清理当前操作拥有的临时目录和锁；清理失败保留准确路径与可诊断锁。空的历史失败安装目录可重用，非空未知目录不自动清空。已激活后不因单个 Agent 失败盲目回滚本体。

## 验证与完成标准

- Windows 默认安装目录，以及中文、空格、单引号和超过 260 字符的文件路径；过长单个组件明确失败。
- ZIP 越界、链接、重复/冲突、错误 CRC、截断、展开超限；路径中的假 node/npm/npx 不可被执行。
- 首次、重复、并发、取消、文件被占用、失败清理，以及 Agent/scheduler 活跃或身份未知的保护。
- 完整包 CLI、SQLite、UI、ripgrep、npm 与 Node 子进程解释器；首次安装 A 后直接复用安装目录验证 npm Agent 和 A→B 更新，核对数据与服务路径。
- 发布后在 Parallels 默认 Windows 环境通过真实 URL 首次安装、从 0.38.0 过渡、调用真实 npm Agent，并在后续版本执行真实 `roll update`。

完成标准是默认 Windows 环境的真实线上安装与升级均通过。单元测试、模拟包和 CI 全绿只能证明各自覆盖范围，不能代替线上验收。
