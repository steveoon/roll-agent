# 单次浏览器委派执行上下文

用户已授权设计并实现。Roll拥有用户目标、值、修改范围、保存/发布权限和跨调用任务；browser_operate仅管理本次明确委派中的执行状态。

## 结构

- execution-context.ts：每次调用的身份、观察版本、初始/当前可观察值、变化记录和最近动作。读取与表单共用，生命周期不跨调用。
- task-progress.ts / task-progress-policy.ts：保留A读取证据与返回语义，接入共享上下文。
- form-context.ts：表单委派schema、字段绑定、可失效满足状态、保留字段与当前焦点。
- form-policy.ts：Jev根据页面绑定委派字段，选择未完成字段及必要的弹窗操作；代码限制动作范围并验证最新状态。
- task-loop.ts：唯一观察→决策→执行循环，提交本轮有效绑定/判断后再决定能否执行旧动作。

不建设通用插件框架、第二个session、跨调用恢复或业务阶段规划器。不写死BOSS字段顺序，不扩大导航权限。

## 表单委派

新增可选formTask，包含mode=create/edit（由Roll指定，不能从空字段猜测），以及明确fields。set字段引用values中的唯一valueName；preserve字段只允许观察，使用调用开始时的值作为基线。恢复一个保留字段必须由Roll明确改为set并提供目标值，工具不自行扩大写入范围。

字段name描述语义而非selector，Jev选择实际已观察字段或编辑入口。未见、截断、遮挡、节点替换均不得推断为空。literal比较由代码完成；semantic比较仅用于有当前可读值的绑定字段，由Jev做局部匹配，不调用宿主。

## 状态与顺序

字段当前状态为unknown/unsatisfied/satisfied，从最新可读证据计算。历史变化保持，但不作为永久完成标记。每次提供初始值、上次值、当前值、关联的最近动作和当前焦点；记录“某动作后观察到变化”，不无依据声称因果。

字段映射和语义状态题合并进当前Jev请求。绑定或状态依据变化时丢弃旧分支动作，下一轮使用新状态。Jev仍选择前置字段和操作顺序。只有所有委派字段有当前满足证据、没有待应用弹窗、且终点判断成立，才能交回interaction_done，仍verified:false。

已有绑定控件、已确认的同一picker选项，以及确认归属于当前焦点的新弹窗内操作，可以在本次委派内执行。未知弹窗或未知归属先确认关系；不能靠相邻位置默认扩大范围。保留字段及明确范围外字段不允许直接修改；间接变化记录并报告。

## 验证

1. 同一个初始值与本次写入、后续重置可以区分。
2. 变更前置字段后，只修复委派范围内明确不满足的字段；未改变字段不重复填。
3. 缺失/遮挡字段为unknown，恢复观察后重新判断。
4. 弹窗内值不等于已应用到主表单。
5. 范围外变化返回证据，不扩大修复范围；preserve约束变化交回。
6. 绑定/语义判断变化时不执行旧候选动作。
7. A读取往返与普通未启用formTask的表单行为兼容。
8. 真实DOM及TypeSafe官方Jev验证，环内宿主辅助为0。

第一版以可观察的原生字段、picker和归属明确的编辑弹窗为范围。未提供可靠当前值的复合摘要保留unknown，不为了宣布成功虚构应用状态。实际BOSS发布岗位的修改不在测试范围；编辑/重置用隔离页面验证。

## 实现补充

已按上述结构落地。formTask.stopAt增加applied/current-view，区分主表单应用和当前编辑视图停留。表单完成由最新字段证据和这个局部终点推导，移除重复的全任务完成问题；最终观察与Roll统一验收保留。调用接口见[执行上下文参考](../reference-browser-execution-context.md)。此前跨调用记忆扩展不在本方案内，后续任务状态优先由Roll维护。
