# 排查 Companion 后台运行环境

适用于管理页面显示“需要处理配置”、Runtime 离线，或 Companion 启动后反复恢复的情况。
设备已绑定、后台服务已安装，并不代表 Runtime 配置已就绪。

## 查看具体原因

打开 `roll ui` 的 Companion 管理页，查看“后台运行环境诊断”，或运行：

```sh
roll companion status
roll companion doctor --json
```

诊断会列出配置文件、缺失变量及引用位置，例如：

- 变量：`MY_MODEL_KEY`
- 引用：`llm.providers.openai.api-key`
- 影响：阻止 Runtime 启动

同一变量也可以被 Agent、代理或其他配置引用。诊断按引用位置定位，不根据变量名字猜用途。
当前检查覆盖配置中的环境变量引用、后备文件可读性、配置格式和当前模型的启动必需项；
不探测网络、可执行文件 PATH 或远端凭据有效性。

## 分清检查环境

- **后台进程实际环境**：从正在运行的 Companion 进程检查绑定 Workspace 的当前配置。
  配置文件会重新读取，但已运行的 Runtime 不会因此自动热加载；更改配置后重启 Companion。
- **后台环境预检估算**：服务未响应时，仅用服务通常具备的基础变量和后备文件预检。
  不能据此宣称实际服务已经就绪。
- **环境诊断不可用**：仍优先读取后台进程的真实状态，不据此判定 Runtime 离线。
  旧版服务可以继续查询状态、停止服务；升级并重启后再检查环境。

`roll companion doctor` 分别检查服务、Runtime 在线状态和环境。
若无法验证实际服务环境，整体结果不会报告为通过。检查通过也不代表已经调用模型或验证 API Key。

## 补齐后台可读取的变量

交互终端和 macOS launchd / Windows 计划任务启动的进程可能具有不同环境。
只在终端执行 `export`，不一定能让后台服务获得该值。

Roll 配置中的 `${变量名}` 按以下优先级解析：

1. 当前进程中的非空环境变量。
2. `~/.roll-agent/secrets.env` 中的非空值。
3. 两边都没有时保留占位符，由配置或能力检查报告。

可以为服务提供相应环境变量，或在上述文件中增加 `KEY=VALUE` 行。保留已有内容，
macOS/Linux 将文件权限设为 `600`，Windows 保持仅当前用户可访问。不要将密钥值贴入日志或截图。

`secrets.env` 是 Roll 公共配置解析的后备源，不是定时任务专用，也不会自动把所有值注入任意外部子进程。
`scheduler.env` 则只用于定时任务执行环境，不应拿它配置 Companion。
值中残留的 `${...}` 不会递归展开；一个非空但仍含占位符的进程变量也不会被后备值覆盖。

然后执行：

```sh
roll companion restart
roll companion doctor
```

页面也可以点击“重启”，再运行体检。配置问题修正后，新检查会清除对应诊断。
当前选中模型服务的任何配置引用（包括 `base-url`）未解析时，都会阻止 Companion 启动 Runtime。
只有其他 Agent 或未使用模型的配置引用缺失时，会显示提醒，不把它升级为整个 Runtime 的启动阻断。

## 其他情况

- **后备文件无法读取**：检查文件类型、属主和访问权限。不要把“读取失败”当成“文件不存在”。
- **配置无效或需要迁移**：在显示的 Workspace 中运行 `roll doctor`，按指引处理；页面不会回显可能包含凭据的原始 YAML 错误。
- **环境检查通过但 Runtime 仍退出**：查看退出码及安全的错误类别（如 `ENOENT`、`EACCES` 或协议校验失败），核对 Node/Roll 路径与版本。未知启动错误不会统一归为环境变量问题。
- **调用时认证失败**：配置可解析不等于凭据有效；需要单独检查对应服务的认证状态。

诊断仅通过本机管理通道提供，不上传到 Cloud Relay。已有配对、远程工具授权和结构化结果读取规则不变。
