# Errors

| Error | Cause | Recovery |
|-------|-------|----------|
| `Agent not found` / no registered agent matches | Agent was not registered, or the wrong name was used | Run `roll agent list`; then `roll agent info <agent-name>` |
| `Tool not found` / schema mismatch | Wrong tool name, or the subagent contract changed | Run `roll agent tools <agent-name> --json` to fetch current tool names and input schemas from stdout. Treat any stderr `Did you mean: ...` line as a hint, then re-discover instead of guessing. If schemas drifted, re-register the local-path agent |
| Orchestrator behavior follows stale agent instructions | The orchestrator used embedded skill text instead of the currently registered agent skill | Run `roll skills get <agent-name> --include-references --json`, read `content` and `references[]`, then re-check `roll agent tools <agent-name> --json` |
| `batch 模式不接受 agent/tool 位置参数` | `roll run --batch-*` was combined with positional `agent tool` | Use `roll run --batch-stdin --json` and put `agent` / `tool` in each JSON item |
| Batch command exits non-zero | One or more batch items failed; previous items may still have succeeded | Parse stdout JSON array, branch on each item's `ok`, and retry only the failed/recoverable items |
| Browser/profile tool reports `browserInstance is required` or opens the wrong account | Multiple isolated runtimes are configured but the orchestrator did not pin the routing key | Read the target agent `SKILL.md`, then pass the same `browserInstance` in every `roll run --input-json` or every batch item `input`; do not reuse refs or prepared IDs across instances |
| Browser page/window is stale, stuck, or should be closed while the agent stays available | Page/document state or browser runtime state is broken, but the `browser-use-agent` service process may still be healthy | First read the target agent `SKILL.md` for documented page-level reload/recovery tools and use them when available; discard old refs and re-read state. If page recovery is unavailable or insufficient, run `roll browser stop <browserInstance>` for one instance or `roll browser stop --all` for all started instances, then retry with the same routing key. Do not use `roll agent stop browser-use-agent` unless the service process itself must stop |
| Browser profile/session data must be reset | The persisted `userDataDir` or `sessionsDir` state is intentionally being discarded | Run `roll browser clear-data [browserInstance]` first to inspect the dry-run plan, then rerun with `--yes` only after confirming the declared paths. Stop the runtime first when possible |
| `roll browser stop <instance>` reports not found | The requested browser instance is not declared for the current config | Check `browser.instances` and `roll run browser-use-agent browser_status --json`, then retry with a declared `browserInstance` |
| Connection error / timeout | Target agent is a persistent service and is not healthy | Run `roll agent info <agent-name>` to confirm runtime ownership, then `roll agent health --json`; if Roll owns lifecycle, run `roll agent start <agent-name>` |
| `roll agent health --json` reports sidecar version mismatch | Runtime metadata was created by another Roll version | If `runtime ownership` is `core-managed`, run `roll agent stop <agent-name>` then `roll agent start <agent-name>`; if external-managed, report the mismatch |
| `roll agent health --json` reports orphan sidecar / stale runtime metadata | Metadata exists but the recorded process is gone or unrelated | Run `roll doctor --fix --json`, then `roll agent health --json` again |
| `roll agent health --json` reports PID mismatch | Sidecar PID does not match the process Roll is checking | Restart only core-managed agents; for external-managed agents, report the process mismatch to the user |
| `needs_input` from `roll ask --json` | The router found a tool, but required inputs could not be extracted safely | Read both arrays from stdout JSON: `validationIssues` (input schema) and `runtimeIssues` (runtime prerequisites). The mirrored two-section message on stderr is diagnostic only. Switch to `roll run <agent> <tool> --input-json '{...}' --json` after resolving both |
| Tool error with `cause: ...` line in stderr | The target agent wrapped an upstream error with `Error.cause`; Roll prints it below the main message | Read the stderr `cause: ...` line for the original error (URL, `timeoutMs`, `requestId`, upstream HTTP status, etc.). Stdout remains the tool/JSON payload channel. Use `requestId` to correlate with upstream service logs |
| `needs_confirmation` from `roll ask --json` | Routing confidence was below the confirm threshold | Confirm the agent/tool explicitly, or bypass routing with `roll run` |
| `roll agent install /path/to/local-agent` fails | A local source directory was treated like a package spec | Use `roll agent add /path/to/agent` instead |
| `roll agent install` / `roll update` reports npm network, timeout, `ETIMEDOUT`, `ECONNRESET`, or `ENOTFOUND` | npm registry access is slow, blocked, or unstable | Check VPN/proxy first. If the environment needs a mirror, run `roll config explain install.registry` then `roll config setup install`; rerun the command. Do not change the agent package spec to work around registry reachability |
| `install` config validation fails before install/update | The `install` section in `roll.config.yaml` is malformed, e.g. invalid `registry` URL or out-of-range `fetch-retries` | Fix the `install` section first, preferably through `roll config setup install`. Roll should stop instead of silently falling back to npm's default registry, especially when a private or mirror registry was intended |
| Agent tool returns 401 / missing config / wrong endpoint behavior | Agent runtime did not receive required env vars, or upstream provider rejected the supplied key | First run `roll doctor --json` for drift summary, then `roll agent info <agent-name>` for per-key runtime labels. Run `roll config explain agents.env.<agent-name>` and `roll config setup agent <agent-name>`, restart or re-register as needed, and only after that verify provider/key validity |
| `roll config setup` reports that an interactive terminal is required | The command was run in a non-TTY environment (CI, pipe, or detached automation) | Use `roll config set <key> <value>` or edit `roll.config.yaml`; run `roll config explain <path>` for field guidance |
| `roll config setup` exits non-zero after user cancellation | The wizard was interrupted before completion | Do not treat as success; rerun `roll config setup` or apply changes with `roll config set` |
| Local-path agent behavior does not match current source tree | Registration metadata is stale after upstream edits | Run `roll agent remove <agent-name>` and `roll agent add /path/to/agent` again |
| Tool error mentions `preparedReplyId 已过期` / `preparedReplyId 不存在` | The opaque prepared artifact expired or was never created in the current browser-use process | Re-run the documented preview/generate tool for the same routing key, then continue with the new `preparedReplyId` |
| Tool error mentions `preparedReplyId 已消费` | The prepared artifact was already sent/consumed | Generate a fresh preview; do not reuse the old `preparedReplyId` or prior approval object |
| Judge returns `fallback:true` with a safe reason code | Rubric fetch/hash, variant shape, Judge sampling, or Judge output validation failed | Omit `variantDecision` and call the sender with only `preparedReplyId`; the sender sends the recommendation and submits `not_learned` without Beta evidence |
| Send returns `feedbackStatus:"queued"` | The candidate message was sent, but feedback POST had a retryable failure | Do not rerun send. The SQLite outbox retries only feedback until `feedbackExpiresAt` |
| Send returns `feedbackStatus:"failed"` | The candidate message was sent, but feedback could not be queued or permanently failed | Do not rerun send. Fix token/service/outbox configuration and treat this as a feedback gap |
| After upgrading Roll, feedback is rejected or fallback outcomes appear as learned/legacy | New browser-use feedback fields reached an older Reply Authority schema that rejected or stripped them | Deploy Reply Authority RFC V3 before the new browser-use agent; do not use the mixed version for learning |
| Send tool returns `needs_confirmation` | Tool-level or browser action policy requires explicit approval | Retry the same send with the same routing key, `preparedReplyId`, `variantDecision`, reason, and approval object from the prior response; if any of those inputs change, treat it as a new send |

Subagent-specific business errors should be diagnosed against that subagent's own docs rather than this shared Roll skill.
